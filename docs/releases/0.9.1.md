### 修复和改进

- 配置里有 mihomo 不支持的 XPro 节点（FlowBar 0.5.0 到 0.8.2 的 rill 内核专有）时，连接时自动跳过这些节点，不再整个配置检查失败，也不必先手动删掉。
- 直接编辑已导入的 YAML 删掉节点后，策略组和规则里残留的旧名称会在连接时自动去掉；节点全被删掉的策略组随之停用，只指向它的规则也一并跳过。此前每次连接都会因为悬空引用校验失败，重启也无效。导入的 YAML 本身不会被改动，跳过的内容记在会话日志里。
- 恢复上次的节点选择前先核对节点和策略组是否还在，已不存在的选择会被忘掉，不再每次连接都尝试恢复。
- TUN 模式下，连向代理服务器本身的连接一律直连，避免这类连接被 TUN 截获后再次送进代理、反复回流直到超时；配置里固定的 `interface-name` 在 TUN 模式下不再生效，改由内核跟随当前的默认网络出口，切换网络后代理服务器仍然可达。
- 配置检查或内核启动失败时，提示里直接给出 mihomo 报告的具体原因（例如缺少哪个节点或策略组），不再只说「请打开日志」。
- macOS 上 TUN 网卡名交给 mihomo 按 `utunN` 规则自动分配，不再先用不被接受的 `utun` 再由内核重新生成。
- 内核日志级别使用配置里的 `log-level`，没有设置时为 `info`。此前固定为 `debug`，设成 `warning` 也会输出大量调试日志。
